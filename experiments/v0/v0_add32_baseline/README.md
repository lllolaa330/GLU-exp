# V0 / add32：正确性与完整求解时间检查点

数据来自服务器已有运行目录 `experiments/v0/add32-repeat-3rE4Wh`，只读下载，未修改服务器文件。图与表由 `analyze.py` 从原始日志生成，没有手填测量值。

## 实验定义

- numeric.cu 基线 SHA-256：aa4b0521c3b5958b35fef51a2973dc347b01a9fffe3ee0ca6864da9f612a9d7d。
- 矩阵 add32_csr.mtx，4960 个未知数，两边右端向量均为全 1。
- 每轮依次运行 KLU_standalone、GLU，再比较解的相对 L2 误差；每次求解启动新进程。
- 第 0 轮按事先约定作为预热保留，不计入汇总；正式轮次 1–5 全部保留，包括 KLU 第 5 轮较慢的样本。
- 完整计时从读取/准备输入前，到主机解向量就绪；包含必要传输和同步，不包含残差验证、写解文件。没有测量常驻上下文或多次复用。
- GLU 的解以 scientific / setprecision(17) 输出；KLU 输出 %.17g。原版分解算法未因测量准备而优化。

## 结果与解释

KLU 中位数 10.498933 ms，GLU 中位数 76.133 ms。主加速比采用中位数之比：10.498933 / 76.133 = 0.137902526。GLU 在本矩阵上约慢 7.2515 倍。

正式轮 GLU 范围为 73.0047–77.3245 ms，KLU 为 10.4468–14.442169 ms。最大相对 L2 误差为 2.70242173258018645e-15；包含预热的 6 轮都通过 1e-6 判据。这里只证明当前矩阵的正确性，不能推广到全部矩阵。

先前单次完整 GLU 时间 8753.89 ms 在这组运行中未复现。原日志应保留在服务器 add32-timing 目录；本图不混入它，因为它不是预先定义的这组连续轮次。原因尚未确定。

正式轮旧的 GPU 事件时间为 17.1668–19.2146 ms，不是纯 LU 内核时间。它与完整墙钟时间来自不同计时范围，差值只能提示范围之外存在开销，不能直接命名为初始化、CPU 求解或某个阶段。现有 Symbolic/CSR 等日志使用 CPU user time，不能与 GPU event time 拼成墙钟时间堆叠图。

## 文件与复现

- baseline.png / baseline.svg：三幅图（KLU 时间、GLU 时间、解误差）；两个时间子图纵轴尺度不同，均从零起。
- samples.csv：所有 6 轮，包括预热标记、旧 GPU 事件时间和逐轮时间比值。
- summary.json：正式 5 轮统计，主加速比为中位数之比，而不是逐轮比值的平均值。
- add32-repeat-3rE4Wh/：原始日志、解向量、设备前后快照。
- analyze.py：只分析数据、不运行求解器。已有 matplotlib 环境中运行 `python3 analyze.py` 可重新生成结果。

这是 V0 的一个测量检查点，不标记为 V0 全部完成，不推进到 V1。
